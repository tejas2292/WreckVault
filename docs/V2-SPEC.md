# WreckVault v2 — build contract

This file is the single source of truth for the v2 rebuild. Server, data layer and UI are
built in parallel against it. If something here is ambiguous, pick the safest reading and
note it in your final report; do not invent a different contract.

**This repository is public.** Never commit real hostnames, IP addresses, usernames,
passwords, tokens or personal data — not in code, tests, fixtures, comments or docs. Use
`example.com`, `10.0.0.x`, `alice`, `correct horse battery staple`, etc.

---

## 0. Non-negotiables

1. **No data loss.** v2 is additive. Never `DROP`, `TRUNCATE`, `DELETE` from or `UPDATE`
   rows of the existing `vault_entries` table, and never modify `users.password_hash`
   (except the existing account-deletion route, which already deletes them on purpose).
   All new data lives in new tables/columns. Rolling back to the v1 app must keep working
   for every entry that existed before the upgrade.
2. **Zero knowledge.** The server never sees the master password after the v1→v2 upgrade
   call, never sees any key, never sees item contents. It sees: ids, collection ids, item
   type, timestamps, ciphertext.
3. **Works over plain HTTP on the LAN.** The app is opened at `http://<lan-ip>:3011`, which
   is NOT a secure context: `crypto.subtle`, `crypto.randomUUID` and
   `navigator.clipboard` are unavailable there. Use `@noble/ciphers`, `@noble/hashes`,
   `hash-wasm` and `crypto.getRandomValues` (which IS available). Clipboard must fall back
   to a hidden-textarea `document.execCommand('copy')`.
4. **Cold-boot resilience stays.** The API must survive Postgres starting after it
   (keep the current retry loop: 30 tries × 5 s, then exit 1 so Docker restarts it).

## 1. Database schema (additive migrations in `server/db.js`)

Existing tables `users`, `vault_entries`, `login_logs` stay exactly as they are. Add:

```sql
ALTER TABLE users ADD COLUMN IF NOT EXISTS auth_version INTEGER NOT NULL DEFAULT 1;  -- 1 = legacy, 2 = v2
ALTER TABLE users ADD COLUMN IF NOT EXISTS auth_hash TEXT;            -- bcrypt(authHash), v2 only
ALTER TABLE users ADD COLUMN IF NOT EXISTS kdf_salt TEXT;             -- base64, 16 bytes
ALTER TABLE users ADD COLUMN IF NOT EXISTS kdf_params JSONB;          -- {"alg":"argon2id","m":65536,"t":3,"p":1}
ALTER TABLE users ADD COLUMN IF NOT EXISTS wrapped_vault_key TEXT;    -- sealed blob, see §3
ALTER TABLE users ADD COLUMN IF NOT EXISTS upgraded_at TIMESTAMPTZ;

CREATE TABLE IF NOT EXISTS server_settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);

CREATE TABLE IF NOT EXISTS collections (
  id UUID PRIMARY KEY,                       -- generated by the client
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name TEXT NOT NULL,                        -- plaintext; collection names are not secret
  kind VARCHAR(20) NOT NULL DEFAULT 'custom',-- personal | alfred | custom
  agent_access BOOLEAN NOT NULL DEFAULT false,
  wrapped_key TEXT NOT NULL,                 -- collection key sealed with the vault key
  sort INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS items (
  id UUID PRIMARY KEY,                       -- generated by the client
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  collection_id UUID NOT NULL REFERENCES collections(id),
  type VARCHAR(32) NOT NULL,                 -- one of TYPE_KEYS in client/src/lib/itemTypes.js
  encrypted TEXT NOT NULL,
  legacy_entry_id INTEGER,                   -- vault_entries.id this item was migrated from
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,                    -- set = in trash
  UNIQUE (user_id, legacy_entry_id)
);
CREATE INDEX IF NOT EXISTS idx_items_user ON items (user_id);

CREATE TABLE IF NOT EXISTS item_history (
  id SERIAL PRIMARY KEY,
  item_id UUID NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  collection_id UUID NOT NULL,
  type VARCHAR(32) NOT NULL,
  encrypted TEXT NOT NULL,                   -- the version that was replaced
  version_updated_at TIMESTAMPTZ NOT NULL,   -- that version's updated_at
  replaced_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_item_history_item ON item_history (item_id);
```

Valid `type` values: `login api_key ssh_host database server vpn cloud_credential webhook
card secure_note identity wifi license`. The server rejects anything else with 400.

## 2. HTTP API (JSON, all under `/api`)

**Session:** an httpOnly cookie `wv_session` holding an HS256 JWT `{uid, v}` (v = auth
version), 12 h expiry, `SameSite=Strict`, `Path=/`, `Secure` only when the request is HTTPS
(`req.secure` with `app.set('trust proxy', 'loopback, linklocal, uniquelocal')`). The JWT
secret is 48 random bytes stored in `server_settings` under `jwt_secret` (created on first
boot). No `x-user-id` header anywhere any more.

**CSRF:** every non-GET request must carry `X-WV-Client: 1`; otherwise 403
`{error:"Missing client header"}`. Remove the wildcard `cors()`; the app is same-origin.

**Errors:** always `{ "error": "<sentence a person can act on>" }` with a fitting status.
`401` = no/invalid session. `409` = auth-version mismatch or duplicate id.

**Body limit:** `express.json({ limit: '25mb' })` (attachments are inline, max 1 MB each).

**Ids:** client-generated UUID v4, validated with
`/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i`.

### Auth

| Method & path | Auth | Body | Response |
|---|---|---|---|
| `GET /health` | – | – | `{ok:true, db:true}` or 503 `{ok:false, db:false}` |
| `GET /auth/status` | – | – | `{registrationOpen: bool}` — true when `users` is empty or env `ALLOW_REGISTRATION=true` |
| `POST /auth/prelogin` | – | `{username}` | v1 user → `{authVersion:1}`; v2 user → `{authVersion:2, kdf:{salt, params}}`; unknown user → a v2-shaped answer whose salt is the first 16 bytes of `HMAC-SHA256(jwt_secret, "prelogin:"+username)` (base64) and default params, so usernames can't be probed. Rate limit 30 / 15 min / IP. |
| `POST /auth/login` | – | v1: `{username, password}`; v2: `{username, authHash}` | `200 {user, authVersion, kdf, wrappedVaultKey}` + sets cookie. v1 user sending `authHash`, or v2 user sending `password` → 400 "Invalid credentials". Keep the existing limiter (4 failed / 15 min / IP, `skipSuccessfulRequests`) and keep writing `login_logs` rows exactly as today. |
| `POST /auth/logout` | – | – | `{ok:true}`, clears cookie |
| `POST /auth/register` | – | `{username, authHash, kdf:{salt, params}, wrappedVaultKey, collections:[{id, name, kind, agentAccess, wrappedKey}]}` | 403 when registration is closed; 400 username taken; `200 {user, authVersion:2, kdf, wrappedVaultKey}` + cookie. Creates a v2 user directly: `password_hash` gets `bcrypt(authHash)` too (column is NOT NULL), `auth_hash = bcrypt(authHash)`. |
| `GET /auth/me` | session | – | `{user, authVersion, kdf, wrappedVaultKey}` (kdf/wrappedVaultKey null for v1) |
| `PUT /auth/me` | session | `{profileImage}` (data URL or null) | `{user}` |
| `DELETE /auth/me` | session | v1 `{password}` / v2 `{authHash}` | re-verifies, then deletes the user's items, collections, history, vault_entries and the user (single transaction); clears cookie |
| `POST /auth/upgrade` | session, v1 only (else 409) | `{password, authHash, kdf:{salt, params}, wrappedVaultKey, collections:[...same as register], items:[{id, collectionId, type, encrypted, legacyEntryId, createdAt, updatedAt}]}` | One transaction: re-verify `password` against `password_hash` (400 if wrong); insert collections and items; **reject with 400 unless the set of `legacyEntryId`s equals exactly the set of this user's `vault_entries.id`s**; set `auth_hash`, `kdf_salt`, `kdf_params`, `wrapped_vault_key`, `auth_version=2`, `upgraded_at=now()`. `password_hash` and `vault_entries` are not touched. Re-issue the cookie with v=2. Response `{user, authVersion:2, kdf, wrappedVaultKey, migrated:<n>}`. |
| `POST /auth/change-password` | session, v2 | `{currentAuthHash, newAuthHash, kdf:{salt, params}, wrappedVaultKey}` | verify current → update `auth_hash`, `kdf_salt`, `kdf_params`, `wrapped_vault_key` atomically. `{ok:true}` |
| `GET /auth/login-logs?limit=N` | session | – | same rows as today (default 100, max 500), camelCase keys `{id, username, ipAddress, success, userAgent, createdAt}` |

`user` object everywhere: `{id, username, createdAt, profileImage}`.

### Legacy (v1 data, read-only)

| `GET /legacy/entries` | session | – | this user's `vault_entries` rows, camelCase: `{id, serviceName, accountUsername, encryptedBlob, websiteUrl, category, entryType, isFavorite, createdAt, updatedAt}` |

### Collections & items (session with v=2; v1 session → 409 "Upgrade your vault first")

| Method & path | Body | Response |
|---|---|---|
| `GET /collections` | – | `[{id, name, kind, agentAccess, wrappedKey, sort, createdAt}]` |
| `POST /collections` | `{id, name, kind:'custom', agentAccess:false, wrappedKey}` | the row |
| `GET /items` | – | all the user's items incl. trashed: `[{id, collectionId, type, encrypted, legacyEntryId, createdAt, updatedAt, deletedAt}]` |
| `POST /items` | `{id, collectionId, type, encrypted}` | the row (409 if id exists) |
| `PUT /items/:id` | `{collectionId, type, encrypted}` | copies the current row into `item_history`, then updates; returns the row. 404 if not the user's. |
| `DELETE /items/:id` | – | soft delete: sets `deleted_at`; returns the row |
| `POST /items/:id/restore` | – | clears `deleted_at`; returns the row |
| `DELETE /items/:id/permanent` | – | only when already in trash (else 409); hard-deletes item + history; `{ok:true}` |
| `GET /items/:id/history` | – | `[{id, collectionId, type, encrypted, versionUpdatedAt, replacedAt}]` newest first |

Every query is scoped by `user_id`; a `collectionId` that isn't the user's → 400.

## 3. Cryptography (client only; `client/src/crypto/`)

Encoding: base64 (standard, with padding) for all binary in JSON.

```
masterKey  = Argon2id(password UTF-8, salt = 16 random bytes, m = 65536 KiB, t = 3, p = 1, len = 32)   // hash-wasm
encKey     = HKDF-SHA256(ikm = masterKey, salt = empty, info = "wreckvault/v2/enc",  len 32)           // @noble/hashes
authKey    = HKDF-SHA256(ikm = masterKey, salt = empty, info = "wreckvault/v2/auth", len 32)
authHash   = base64(authKey)                       // the only thing sent to the server; server bcrypts it (cost 12)

seal(key, plaintextBytes, aadString)  -> "wv1." + base64(nonce12) + "." + base64(ciphertext||tag)       // AES-256-GCM, @noble/ciphers gcm
open(key, sealedString, aadString)    -> bytes, throws on any failure

vaultKey        = 32 random bytes            wrappedVaultKey = seal(encKey,   vaultKey, "wreckvault/v2/vault-key")
collectionKey   = 32 random bytes            wrappedKey      = seal(vaultKey, collKey,  "wreckvault/v2/collection:" + collectionId)
item.encrypted  = seal(collectionKey, UTF-8(JSON.stringify(payload)), "wreckvault/v2/item:" + itemId + ":" + type)
```

* Unlock = derive keys, `open(encKey, wrappedVaultKey)`; a GCM failure means "Wrong master password".
* Every create/update re-encrypts with a fresh nonce. Moving an item to another collection
  or changing its type re-encrypts with that collection key / type in the AAD.
* History entries are opened with the AAD built from that history row's `type`.
* Random bytes: `crypto.getRandomValues`. UUID v4: build from `getRandomValues` (never `crypto.randomUUID`).
* Keys live only in memory (module-level, never React state that devtools persist, never
  storage). Lock = drop them.

### Item payload (the decrypted JSON)

```json
{
  "v": 1,
  "title": "GitHub",
  "fields": [ { "id": "f1", "label": "Username", "kind": "text", "value": "alice" } ],
  "notes": "",
  "tags": ["dev"],
  "project": "",
  "favorite": false,
  "status": "active",
  "supersededBy": null,
  "links": [],
  "attachments": [ { "id": "a1", "name": "id_ed25519", "mime": "application/octet-stream", "size": 411, "data": "<base64>" } ]
}
```

`kind` ∈ FIELD_KINDS keys; `status` ∈ `active | superseded | revoked`; field and attachment
ids are short random strings. Attachments are capped at 1 MB each (UI enforces).

## 4. v1 → v2 upgrade (client data layer)

After a v1 user logs in (raw password kept in memory only for this step):

1. `GET /legacy/entries`; decrypt each `encryptedBlob` with `CryptoJS.AES.decrypt(blob, password)`
   exactly like v1 (`toString(Utf8)`, empty string = failure; card/note must also `JSON.parse`).
2. Map every row to exactly one v2 item in the **Personal** collection (ALFRED starts empty):

| v1 row | v2 item |
|---|---|
| `entryType` `password` (or null) | `login`: title = serviceName; fields Username(text)=accountUsername, Password(secret)=decrypted, Website(url)=websiteUrl — omit empty ones except Password |
| `card` | `card`: title = serviceName; Cardholder(text)=cardholder_name, Number(secret)=card_number, Expiry(mono)=`MM / YY` from expiry_month/expiry_year (keep raw values if they don't fit), CVV(secret)=cvv, Card type(text)=card_type; keep any extra JSON keys as text fields named after the key |
| `note` | `secure_note`: title = serviceName; Content(multi)=content |
| any row that fails to decrypt or parse | `secure_note` titled `"<serviceName> (could not decrypt)"`, tag `legacy-undecryptable`, fields: Username(text), Website(url) when present, and **Original encrypted data**(multi) = the untouched `encryptedBlob`; notes explain it was encrypted with an older password and is kept unchanged |

   Every item: `tags` = `[category]` when category is set and not `other`; `favorite` =
   isFavorite; `legacyEntryId` = row id; `createdAt`/`updatedAt` copied from the row.
3. Verify before sending: one item per row; for every item, `open()` its ciphertext again and
   deep-compare with the payload built in step 2. Abort on any mismatch.
4. `POST /auth/upgrade`. On success the session is unlocked with the new keys.
5. Before step 4 the UI requires the person to download a backup:
   `wreckvault-backup-before-upgrade-YYYY-MM-DD.json` = the v1 export format
   (`service_name, account_username, password, website_url, category, entry_type,
   decrypted_data, exported_at`) for decryptable rows **plus** the raw row for any that
   didn't decrypt.

## 5. Data-layer interface (consumed by the UI)

`client/src/state/session.jsx` exports `SessionProvider` and `useSession()`:

```
status: 'loading' | 'signedOut' | 'locked' | 'needsUpgrade' | 'unlocked'
user, registrationOpen, error
login(username, password)        -> {ok, error?}   // sets status to unlocked or needsUpgrade
register(username, password)     -> {ok, error?}
unlock(password)                 -> {ok, error?}   // session cookie exists, keys not in memory
lock()                           // drops keys, status 'locked'
logout()                         -> Promise
legacySummary()                  -> {total, decryptable, undecryptable, byType:{password, card, note}}
downloadUpgradeBackup()          -> filename
runUpgrade(onProgress?)          -> {ok, migrated, undecryptable, error?}
changeMasterPassword(current, next) -> {ok, error?}
deleteAccount(password)          -> {ok, error?}
updateProfileImage(dataUrlOrNull)-> {ok, error?}
loginHistory(limit)              -> rows
autoLockMinutes, setAutoLockMinutes(n)   // 0 = off; persisted in localStorage 'wv-autolock'; inactivity timer locks
```

`client/src/state/vault.jsx` exports `VaultProvider` and `useVault()` (valid when unlocked):

```
items        // DecryptedItem[] incl. trashed; sorted by title
collections  // [{id, name, kind, agentAccess}]
loading, error
createItem(draft)            -> DecryptedItem
updateItem(id, draft)        -> DecryptedItem     // draft may change type/collectionId
toggleFavorite(id)           -> DecryptedItem
trashItem(id), restoreItem(id), deleteForever(id)
getHistory(id)               -> [{historyId, replacedAt, item: DecryptedItem}]
restoreVersion(id, historyId)-> DecryptedItem     // saves that version as a new update
exportVault()                -> filename          // plaintext JSON {format:"wreckvault-v2-export", exportedAt, items:[DecryptedItem...]}
importFile(file)             -> {imported, skipped, format}   // accepts v2 export, v1 export array, CSV with headers name,url,username,password,notes (Chrome/Bitwarden style)
refresh()
```

`DecryptedItem = {id, type, collectionId, createdAt, updatedAt, deletedAt, legacyEntryId,
title, fields, notes, tags, project, favorite, status, supersededBy, links, attachments,
decryptError?: true}` — an item that fails to open is still listed with `decryptError` and
title "Unreadable item" so nothing silently disappears.

`client/src/lib/clipboard.js` exports `copyText(text) -> Promise<boolean>` (clipboard API when
available, else textarea fallback) and `scheduleClear(ms=30000)`.
`client/src/lib/totp.js` exports `totpCode(secretOrUri, now=Date.now()) -> "123456"` (RFC 6238,
SHA-1, 30 s, 6 digits, base32 secret; accepts `otpauth://` URIs) and `secondsLeft(now)`.

## 6. UI (from the approved mockup)

The approved clickable mockup is the visual reference (path given to the UI builder). Keep
its look; apply these refinements.

**Tokens** (CSS custom properties in `client/src/ui/styles/tokens.css`; colours exactly as
in the mockup, light on `:root`, dark under `prefers-color-scheme: dark` guarded by
`:root:not([data-theme="light"])` and again under `:root[data-theme="dark"]`):

```
spacing  --s1 4px  --s2 8px  --s3 12px  --s4 16px  --s5 20px  --s6 24px  --s8 32px
type     --fs-xs 11px (uppercase labels, +0.07em)  --fs-sm 12.5px  --fs-md 14px  --fs-lg 15px  --fs-xl 18px  --fs-2xl 22px
         line-height 1.45 body / 1.2 headings; headings letter-spacing -0.015em; text-wrap: balance
radius   --r-sm 6px  --r-md 8px  --r-lg 11px  --r-xl 14px
fonts    Geist Variable (UI), Geist Mono Variable (secrets, hosts, codes, ids) via @fontsource-variable — no Google Fonts request
numbers  font-variant-numeric: tabular-nums wherever digits line up
```

**Layout:** desktop ≥1021 px = framed window (12 px margin, `--r-xl`, shadow) with three
panes: sidebar 232 px · list 340 px · detail fluid (content max 760 px). 681–1020 px: sidebar
becomes a drawer, two panes. ≤680 px: full-bleed (no frame), one pane at a time, sticky top
bars, `100dvh`, safe-area insets on all edges, dialogs become bottom sheets (max 92dvh),
inputs 16 px (stops iOS zoom), every tap target ≥44 px (`@media (pointer:coarse)` as well).

**Rhythm fixes over the mockup:** sidebar rows 32 px with 16 px between groups; list rows
56 px with 12 px padding and the chip/star aligned on one right edge; detail field rows
min 44 px, label column 160 px, row actions always visible on touch; section headings 11 px
uppercase with 8 px gap to their box; consistent 24 px between detail sections.

**Screens:** sign-in (prelogin → derive → login, with a "Deriving key…" state since Argon2
takes ~1 s), create account (only when `registrationOpen`), lock screen, upgrade screen
(summary counts, required backup download, then "Upgrade vault", progress, result),
main app (All items, Favourites, Health, Trash, Generator, Settings in the sidebar;
collections; types with counts; projects), item detail, item editor (create and edit:
type, title, collection, project, tags, fields add/remove/reorder/change kind, secret
generator button on secret fields, notes, attachments ≤1 MB with download, links picker,
status + "superseded by"), history panel with restore, health view, trash view, command
palette (⌘K / Ctrl+K, `/` focuses search), settings (theme system/light/dark, auto-lock,
change master password, export, import, login history table, profile image, delete
account with typed confirmation), generator (port the existing password + JWT-secret
generator page faithfully). In-app confirm dialogs and toasts replace sweetalert2.
Copying a secret shows a toast and clears the clipboard after 30 s (best effort).

Copy: plain, specific, active voice; errors say what went wrong and how to fix it. No emoji.

## 7. Infrastructure

* `server/Dockerfile`: `node:20-alpine`, `npm ci --omit=dev`, source baked in, `CMD ["node","index.js"]`.
* `client/Dockerfile`: multi-stage — `node:20-alpine` builds, `nginx:1.27-alpine` serves `dist/` on port 80.
* `client/nginx.conf`: SPA fallback; `/api/` → `http://backend-api:5000` with `X-Forwarded-For`
  and `X-Forwarded-Proto` (keep an incoming proto from a tunnel); `client_max_body_size 30m`;
  gzip; long cache for `/assets/`, no-cache for `index.html`; headers: CSP
  `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`,
  `X-Content-Type-Options nosniff`, `Referrer-Policy no-referrer`.
* `docker-compose.yml` (production): same service and container names, networks and the
  `x-casaos` block as today; client `ports: "3011:80"`, no `command:`, no source volumes on
  either service (an old anonymous `node_modules` volume would hide new dependencies).
* `docker-compose.dev.yml`: Postgres 16 (host port 55432) + API + client on host port 8088,
  for local end-to-end testing. Different project name; no clash with production names.
* CI (`.github/workflows/deploy.yml`): Node 20; client lint + unit tests + build; server
  tests against a `postgres:16` service container; deploy job unchanged except
  `docker compose -p wreckvault up -d --build`.
